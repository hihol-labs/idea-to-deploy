# SCOPE_LOCK — INSTALL-HARDENING (открыт 2026-08-29)

## Предмет
**Юнит сужен до P2 решением владельца 2026-08-29** (см. «Сужение» ниже).
Дефект из `docs/retros/RETRO-2026-08-29.md`, воспроизведён машинно на боевом
маршруте релиза v1.101.0. Юнит чинит ПРИЧИНУ, а не симптом.

**P2 — установленный runtime портится собственным байткодом.**
`hooks/check-review-before-commit.sh` (и тем же приёмом
`check-dod-before-commit.sh`, `pii-egress-guard.sh`) грузит модуль через
`SourceFileLoader.exec_module`. Когда путь резолвится в УСТАНОВЛЕННЫЙ runtime,
интерпретатор пишет `__pycache__/*.pyc` рядом с загружаемым файлом, то есть
внутрь content-addressed каталога. `itd_install_runtime.py` справедливо считает
лишний каталог дрейфом и блокирует reinstall («installed runtime directory
inventory drifted», 39 файлов против 38 в манифесте), причём НЕ называет, какой
именно путь лишний.

## Сужение до P2 (решение владельца 2026-08-29)
P3 (`sync-to-active.sh` на не-UTF-8 `settings.json`) **выведен из юнита** и
возвращён в BACKLOG. Причина — не нехватка времени, а сработавшее стоп-правило
над СОДЕРЖАНИЕМ: ключ механизма «`sync-to-active.sh` + порядок проб кодировок»
повторился в двух РАЗНЫХ раундах на изменившемся кандидате (r3: `utf-8-sig`
перед `utf-8` добавлял BOM обычному UTF-8; r5: cp1251 перед cp1252 молча
искажает валидный cp1252). Повтор ключа означает дефект ФОРМЫ решения:
однобайтовые кодировки декодируют почти любые байты, поэтому «пробовать по
списку и ловить исключение» в принципе не различает cp1251 и cp1252. Новая
форма требует отдельного решения владельца и отдельного юнита; работа
сохранена патчем `.itd-memory/p3-settings-encoding-attempt.patch`.

## Допущения владельца
- P2 чинит только причину и диагностику. Гарантия inventory остаётся строгой:
  любой лишний байт по-прежнему блокирует reinstall; флаг `--prune-bytecode`
  НЕ вводится.

## Разрешённые области
- `hooks/check-review-before-commit.sh`, `hooks/check-dod-before-commit.sh`,
  `hooks/pii-egress-guard.sh` — запрет записи байткода вокруг загрузки модуля.
- `scripts/itd_install_runtime.py` — только текст ошибки inventory (называет
  конкретный лишний путь + FIX); правила сверки не ослабляются.
- Тесты: `tests/verify_itd_runtime_install.py`.
- Артефакты САМОГО сужения (появились вместе с ним, 2026-08-29): `BACKLOG.md`
  — пункт P3 с обеими отвергнутыми формами; `.itd-memory/p3-settings-encoding-attempt.patch`
  — сохранённая работа P3, чтобы вывод части из юнита не означал её потерю.
- Леджерная бухгалтерия юнита: `.itd-memory/STATE.json`,
  `.itd/ACCEPTANCE_CONTRACT.json`, `.itd/SCOPE_LOCK.md`, `.itd/DECISIONS.md`,
  `.itd-memory/contracts/INSTALL-HARDENING.md`, `.itd/IMPACT_GRAPH.json`
  (производный артефакт: регенерируется `tests/build_impact_graph.py`, когда
