# CODEX-HOOK-TIMEOUT-1: ITD gates in Codex on Windows never race their own timeout

## Current Task

- CODEX-HOOK-TIMEOUT-1 (risk tier high: hook registrations are a critical ITD mechanism). The criteria and their
  verification commands live only in `.itd/ACCEPTANCE_CONTRACT.json` (CODEX-HOOK-TIMEOUT-1-AC1..AC2); this file
  references them and does not restate them.
- Start from main `40a797278cfb4b57e03d7ef37668a224f3f94c04` (v1.110.3). REL-1.110.3 is closed `blocked`: published and
  rolled out, the owner re-trusted the hooks, the live canary is green on WSL and red on Windows; this unit is the only
  open one (WIP=1).
- Root cause from an app-server hook trace on Windows: Codex 0.166 re-checks the plugin content fingerprint before every
  hook run inside the hook timeout; 11 parallel PreToolUse hooks took 4.2-5.07 s each, so a 5 s timeout made the
  external-write gate a race.

## Allowed Change Areas

- `hooks/hooks.json` and `skills/adopt/references/codex-project-hooks.json`: only the `timeout` values.
- `tests/verify_host_adapters.py` (the minimum Codex hook timeout).
- Docs: `docs/CODEX_ADAPTER.md`, `docs/RELEASE_RUNBOOK.md` (rollout step 7a), `CHANGELOG.md` (Unreleased).
- `.itd/IMPACT_GRAPH.json`, only if mechanically regenerated by `tests/build_impact_graph.py`.
- Live-model evidence: one new immutable run under `tests/fixtures/live-model-evidence/runs/` and `latest.json` if the
  benchmark pin (it includes `hooks/`) requires a re-record; existing runs on main are never modified.
- Ledgers: `.itd-memory/STATE.json` and `.itd-memory/events.jsonl` through `itd_unit_log.py` only,
  `.itd/ACCEPTANCE_CONTRACT.json`, `.itd/DECISIONS.md`, `BACKLOG.md`, this file.

## Forbidden Change Areas

- `hooks/codex-dispatch.py`, every hook script and its dispatcher deadlines; the Claude Code registrations in
  `scripts/sync-to-active.sh`.
- The Codex plugin package contents (a smaller package is BACKLOG P2, a separate unit).
- Writing Codex trust (`config.toml` `hooks.state`, `.hook-trust`) from ITD code.
- `HANDOFF.md`; unit statuses by hand; the efficacy archive and the trust policy.
- Push, PR, merge, tag, release, rollout and global configuration changes without the owner's explicit confirmation.

## Review Rule

One opposite-GPT review of the final candidate after a PASSED committed-head machine receipt; its one receipt under
the bare unit id is accepted by the commit cache, the pre-push gate, `itd pr create` and the closure. If the diff
touches an area outside the allowed scope, pause and reclassify the task before continuing.

## Declared limits

- No repository test can reproduce Codex's per-hook trust check timing; the live proof is the next release's rollout
  (runbook 7a: 3 Windows canary turns, each traced through the app-server, no timed-out hook in any).
- A 30 s timeout removes the fail open but not the ~5 s latency per tool call on Windows (BACKLOG P2).
