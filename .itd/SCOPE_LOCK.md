Measured defect. `DEFAULT_POLICY` in `hooks/completion-gate.sh:102` resolves `bypassAuditLedger` to `.itd-memory/events.jsonl`, and that file is tracked by git. So on any project that does not override the policy, an audited COMPLETION_BYPASS writes a row into a tracked file in the middle of a commit: the working tree stops matching the reviewed candidate, and the exact-tree review gate refuses the very commit the bypass was granted for. The write also goes through a plain `open("a")`, so a symlink planted at the ledger path redirects a trusted append. The same pair of facts lives in a second copy - `audit_completion_bypass` in `docs/templates/itd/itd_hygiene.py:209` - with the same default and the same unguarded writer; leaving that copy behind would make the guarantee true for the commit boundary and false for the close boundary, which is the "one fact in several copies" class already recorded in BACKLOG.
