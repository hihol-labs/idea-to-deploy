# Scope Lock — R1 (LPD-002): «at capacity» — недоступность, и провал транспорта оставляет след

## Current Task

Ответ транспорта модели-ревьюера класса «Selected model is at capacity»
классифицируется бесплатным изолированным продюсером
(`skills/_shared/itd_free_reviewer_producer.py`) как **UNAVAILABLE**, а не
`UNVERIFIED`; при **любом** ненулевом коде возврата транспорта скрабленный
хвост stdout+stderr (суммарно <= 4 КБ) сохраняется рядом с `--report-output`
машиночитаемым файлом. Claim идёт riskTier **medium**: правка ограничена
классификацией отказа транспорта и его диагностикой, не меняет модель доверия,
разделение maker/checker, разрез дифа и то, что принимает любой верификатор.
Первый пункт плана `.itd-memory/LPD-002_UNIT_PLAN.json` (approved владельцем
2026-08-18), WIP=1.

## Корни (измерены, не предположены — retro 2026-08-18, сигнал E2/P2)

1. **`Selected model is at capacity` -> UNVERIFIED (2026-08-18).** Формулировки
   в `CLI_UNAVAILABLE_MARKERS` (:2519-2551) покрывают auth/сеть/квоту, но не
   вместимость модели. Перегрузка провайдера — заведомо недоступность
   транспорта; классификация её как `UNVERIFIED` заставляет вручную повторять
   маршрут. Замер: ~35 мин на одну публикацию.
2. **Провал транспорта не оставляет следа.** `raise_cli_failure` (:2553-2578)
   читает stdout/stderr только чтобы вынести классификацию, и не сохраняет
   ничего. Диагностика 2026-08-18 была доступна лишь внешней обёрткой
   (`scratchpad/dbg_producer.py` вокруг `run_bounded_process`) — то есть
   штатный маршрут не отвечает на вопрос «а что именно ответил транспорт».

## Явно вне скоупа

- Скраббер секретов, подписи, ключи, кэш ревью, разрез дифа по байтам,
  модель доверия maker/checker — не трогаются (границы LPD-002).
- Новые вендоры/транспорты ревьюера.
- Пункты R2-R6 плана — каждый отдельной сессией, WIP=1.
- Bounded retry вокруг транспорта (это R3), профили прогонов (R6).

## Принцип

Журнал отказов — **диагностика, а не квитанция**: он не входит в подпись, и
ошибка его записи не меняет классификацию отказа. Иначе почин дефекта
«недоступность судится как UNVERIFIED» вернул бы тот же класс с другой стороны
(нечитаемый диагностический файл -> ложный UNVERIFIED). Скрабление хвоста
обязательно и пинится отдельной проверкой; остаточный credential после
скраббера -> текст не пишется вовсе (`withheld`).
