# Task Contract — R5 (LPD-002)

## Scope
Точный класс кандидата `ledger-close`: диф равен ровно
`.itd-memory/STATE.json` **и** файлу контракта (оба обязательны), контракт
различается с базовой версией только полями `activeFollowup.status` /
`activeFollowup.closedAt`, базовый followup ещё открыт, И все критерии
закрываемого followup имеют `status: passed`. Для этого класса
`coverage_matrix` отдаёт покрытие ЗАКРЫТОГО юнита (не `None`), а промпт
ревьюера несёт явную строку
`closing commit: coverage inherited from the delivered unit <id>`.
Полный скоуп и зоны правок — `.itd/SCOPE_LOCK.md`.

## Verification Standards
- Оракулы (имена — те же, что в `machine --command`):
  - `review-evidence-oracle` = `python3 -I tests/verify_review_evidence.py`
  - `free-reviewer-producer-oracle` = `python3 -I tests/verify_free_reviewer_producer.py`
- `verificationCommand` пункта плана:
  `python3 -I tests/verify_review_evidence.py && python3 -I tests/verify_free_reviewer_producer.py`
- Полный `bash tests/run-all.sh` -> `DONE fails:none` обязателен: riskTier
  high требует контуры `static + targeted + review + full`
  (`skills/_shared/PROPORTIONALITY_POLICY.json`).
- RED до правки: `tests/verify_review_evidence.py` не существует; у модуля
  `skills/_shared/itd_review_evidence.py` нет ни одного прямого сьюта.
- Мутации в обе стороны — четыре канарейки критерия плюс переблокировка:
  1. **недоблокировка**: любой третий файл (код или `LPD-002_UNIT_PLAN.json`) в
     дифе -> класс НЕ признаётся, кандидат судится как раньше;
  2. правка контракта вне `activeFollowup.status/closedAt` -> класс не
     признаётся;
  3. followup с непройденным критерием -> отказ (`ReviewEvidenceError`);
  4. open followup при close-дифе -> класс не признаётся, требуется
     СОБСТВЕННОЕ покрытие активного юнита;
  5. **переблокировка**: обычный delivery-кандидат по-прежнему требует своего
     покрытия — недостающий impact-класс валит матрицу;
  6. сила маршрута: close-класс не может дать
     `minimumIndependentReviewers < 1`;
  7. **недоблокировка (находка чекера r2)**: диф из одного `STATE.json` без
     перехода контракта -> класс НЕ признаётся. Иначе любой поздний
     ledger-коммит наследовал бы покрытие чужого закрытого юнита;
  8. **недоблокировка (находка чекера r5)**: строка дифа со статусом `A` или
     `D` -> класс НЕ признаётся. Кандидат, создающий или удаляющий леджер,
     не бухгалтерия закрытия.

## Exclusions
- Класс не расширяется за букву approved-критерия. Реальный close этого плана
  трогает ещё `.itd-memory/LPD-002_UNIT_PLAN.json` и потому в класс не
  попадает — осознанный выбор владельца 2026-08-19; разрыв зафиксирован
  находкой в `BACKLOG.md` и проверяется догфудингом ПОСЛЕ мержа.
- Продюсер не ослабляется ради прохождения ledger-close (`designDecisions`
  плана: отвергнуто как Гудхарт).
- Скраббер, подписи, ключи, кэш ревью, новые вендоры/транспорты — `outOfScope`
  плана.
- Пункт R6 — отдельная сессия, WIP=1.

## Durable decisions (обе — в `.itd/DECISIONS.md`)
1. **Поверхность строки наследования — все три промпта.** Критерий называет
   unit-промпт, но `evidenceCoverage` рендерится в `review_prompt` (:1284),
   `_unit_review_prompt` (:1534) и `_integration_review_prompt` (:1611);
   ledger-close на S10 судился именно ПЛОСКИМ промптом. Строка идёт во все три
   через общий хелпер, плюс постоянное поле `coverageSource` внутри самой
   матрицы. Шире буквы критерия -> записано в `oracleAmendments` плана.
2. **`minimum_reviewer_count` клампится к >= 1 для close-класса.** Полное
   наследование дало бы `0` для закрытия low-юнита и `NOT_REQUIRED` от
   продюсера — реальное ослабление маршрута. R5 снимает ЛОЖНЫЙ блок, а не
   ревью.
