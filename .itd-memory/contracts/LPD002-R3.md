# Task Contract — R3 (LPD-002)

## Scope
`scripts/itd.py` + `tests/verify_itd_cli.py` + `docs/RELEASE_RUNBOOK.md`:
`itd pr create` и `itd gate` переживают транспортный флейк GitHub bounded
retry'ем и не создают дублей PR. Полный скоуп — `.itd/SCOPE_LOCK.md`.

## Verification Standards
- `python3 -I tests/verify_itd_cli.py && python3 -I tests/verify_gate_control.py`
  -> exit 0 (RED до правки: `AttributeError`, у CLI нет `with_transport_retry`).
- Две обязательные канарейки внутри `guarded-pr-cli-regression`: ретрай на 403 -> падает
  (операция с `HTTP 403` в причине вызывается ровно один раз, ошибка
  пробрасывается как есть); двойной вызов `create` при существующем PR ->
  падает (`gh pr create` не вызывается, когда `pr_view` вернул PR; после
  транспортного сбоя создания повторная проверка находит PR и второго
  `create` нет).
- Мутации в обе стороны: снятие проверки 401/403/422 -> валит канарейку 403 и
  проверку приоритета над транспортным маркером; снятие pre-create lookup ->
  валит канарейку двойного create; снятие потолка попыток -> валит проверку
  «пять попыток и исчерпание с подсказкой»; возврат `command unavailable` на
  таймаут -> валит проверку честного сообщения о таймауте.
- Полный `bash tests/run-all.sh` -> `DONE fails:none`;
  `python3 tests/verify_live_model_benchmark.py --require-evidence` остаётся
  зелёным (skills/hooks не тронуты) — иначе перечеканка отдельным коммитом.
- Маршрут ревью на коммит (riskTier low = `checkerMode machine_only`,
  `checkerRequired false`, `minimumIndependentReviewers 0`):
  `itd_verification_loop.py machine` (claim `LPD002-R3:general-review`,
  оракулы под именами из контракта) -> `adjudicate` ->
  `itd_review_cache.py record`. Чекер по политике не требуется.
- Перед PR — ОТДЕЛЬНЫЙ pre-PR claim противоположным вендором
  (`--candidate-mode committed-head`, продюсер из authority-снапшота
  `REL198-1b38d1c8-a1`).

## Exclusions
`skills/_shared/itd_gate_control.py` не меняется. Мутации без проверки
идемпотентности (`git push`, ruleset POST) не ретраятся. Пункты R4-R6 не
открываются до `verified` R3.
