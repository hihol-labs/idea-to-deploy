# Task Contract — R2 (LPD-002)

## Scope
`hooks/check-review-before-commit.sh` + `scripts/sync-to-active.sh` +
`tests/verify_review_cache.py` + `docs/RELEASE_RUNBOOK.md`: гейт коммита грузит
`itd_review_cache.py` из ТОГО checkout'а, из которого собран инсталл, в любом
другом проекте — из инсталла. Полный скоуп — `.itd/SCOPE_LOCK.md`.

## Verification Standards
- `python3 tests/verify_review_cache.py && python3 -I tests/verify_git_gate_hooks.py`
  -> exit 0 (RED до правки). Первый оракул БЕЗ `-I`: `-I` подразумевает `-E -P`,
  а оракул импортирует `tests/verification_loop_fixture.py` — под `-I` он не
  стартует вовсе, и это верно до правки тоже.
- Две обязательные канарейки внутри оракула: принудительный installed-only ->
  падает сценарий «бамп версии в дереве» (`methodologyVersion` mismatch);
  принудительный repo-only для НЕ-методологического проекта -> падает канарейка
  изоляции (вендоренный чужой валидатор не должен быть загружен).
- Мутации в обе стороны: снятие якоря провенанса -> валит самоназвавшийся
  проект, чужой checkout и инсталл без провенанса; снятие проверки имени
  плагина -> валит безымянный манифест; снятие совпадения корня -> валит
  подмену через симлинк; installed-only -> валит четыре проверки resolve.
- Полный `bash tests/run-all.sh` -> `DONE fails:none`.
- Маршрут ревью на каждый коммит (riskTier medium = `checkerMode targeted`,
  `checkerRequired true`): `itd_verification_loop.py machine` (claim
  `LPD002-R2:general-review`, оракул под именем из контракта) -> свежий
  чекер другой моделью (sonnet-субагент) -> `adjudicate` ->
  `itd_review_cache.py record`.
- Перед PR — ОТДЕЛЬНЫЙ pre-PR claim противоположным вендором
  (`--candidate-mode committed-head`, продюсер из authority-снапшота
  `REL198-1b38d1c8-a1`). Unit-чекер его не заменяет.

## Exclusions
Валидатор `itd_review_cache.py` и прочие хуки не меняются. `sync-to-active.sh`
внесён в скоуп по решению владельца (2026-08-18): он единственное место, куда
репо писать не может, поэтому только он может дать неподделываемый якорь.
Пункты R3-R6 не открываются до `verified` R2.
