# Task contract — PILOT-P01 (medium)

## Scope
1. Один машиночитаемый источник словарей `skills/_shared/VERDICT_TAXONOMY.json`
   (`taxonomyVersion: 1`): enum `source`, `severity` (в т.ч. допустимые
   значения ПО источнику), `category` (13 значений), mapping легаси, имя файла
   карантина.
2. Валидация на записи в обоих писателях. Невалидная запись НЕ попадает в
   канонический леджер и НЕ теряется: уходит в
   `.itd-memory/review-findings-rejected.jsonl` с причиной, счётчик причин
   ведётся машинно.
3. Каждая новая запись несёт `taxonomyVersion` и `source` (провенанс §7);
   `severity: unspecified` запрещена для `subagent-verdict` (ревьюер всегда
   градуирует собственную находку).
4. Retry-текст хука (`REASON`) называет `category` и перечень значений —
   иначе продюсер отдаёт null, как и было в замере (114/130).
5. Читатель (`itd_retro_scan.py`) нормализует легаси через mapping, не
   переписывая леджер, и показывает счётчик отклонённых.

## Verification standards
- RED-first: каждая гарантия сначала краснеет на мутации, затем зеленеет.
  Мутации: снять enum-проверку category -> красный; принять `unspecified` от
  `subagent-verdict` -> красный; отклонить БЕЗ записи в карантин (молчаливый
  дроп) -> красный; переписать легаси-запись -> красный; убрать `category` из
  `REASON` -> красный.
- Поведенческая проверка: фикстура-транскрипт с валидным и с невалидным
  вердиктом; после прогона хука канонический леджер содержит ровно валидную
  запись со штампом `taxonomyVersion`+`source`, карантин — ровно невалидную с
  причиной, счётчик увеличен.
- Fail-closed на недоступной таксономии: файл словарей отсутствует/битый ->
  запись уходит в карантин с причиной `taxonomy-unavailable`, а не в
  канонический леджер и не в никуда. Хук по-прежнему не роняет сессию.
- Полное зеркало `bash tests/run-all.sh` -> `DONE fails:none` на кандидате.
- Маршрут medium: машинная нога + независимый cross-vendor продюсер.

## Exclusions
- Слепой семантический протокол >=8/10 — юнит PILOT-P02 (decision-фаза).
- Q1-Q9 RSI discovery-backlog.
- Переписывание легаси-записей; изменение block/silent-решения хука.
- Бамп версии/релиз — отдельным решением после мержа.
