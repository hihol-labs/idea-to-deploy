классификация «at capacity» как UNAVAILABLE и append-only журнал отказов

## Verification Standards
- `python3 -I tests/verify_free_reviewer_producer.py` -> exit 0 (RED до правки).
- Мутации в обе стороны: снятие маркера -> падает capacity-проверка; голое
  `capacity` -> падает канарейка легитимного отчёта; снятие скраббера -> падает
  секрет-пин; снятие усечения -> падает проверка 4 КБ.
- Полный `bash tests/run-all.sh` -> `DONE fails:none`.
- Маршрут ревью: `itd_verification_loop.py machine` (staged) -> свежий чекер
  другой моделью (sonnet-субагент) -> `adjudicate` -> `itd_review_cache.py record`.

## Exclusions
Скраббер/подписи/ключи/кэш ревью/разрез дифа не меняются. Публикация (PR, релиз)
— не в этой сессии. Пункты R2-R6 не открываются до `verified` R1.
