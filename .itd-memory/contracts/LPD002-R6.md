# Task Contract — R6 (LPD-002, последний пункт плана)

## Scope
Карта «путь исходника -> сьюты» лежит в репозитории как ДАННЫЕ
(`.itd/IMPACT_GRAPH.json`) и подаётся в СУЩЕСТВУЮЩИЙ `impact_closure`
(`skills/_shared/itd_verification_profiles.py`) как `impactGraph` через новое
поле запроса `impactGraphPath`. Движок получает одну новую операцию
`impact-audit` — машинную **полноту** (каждый `tests/verify_*.py` достижим хотя
бы одним ребром; каждый `skills/_shared/*.py` и `hooks/*.sh` достигает
владеющего сьюта; ни одного узла/цели на несуществующий файл; `impactKnown:false`
по-прежнему -> strict) и **пропорциональность** (замыкание ни одного узла не
покрывает полный набор сьютов). Генератор `tests/build_impact_graph.py` строит
секцию `generated` из tracked-дерева и проверяет свежесть (`--check`); секция
`declared` — ручные рёбра, генератор их сохраняет. Нового движка нет (ADR-001).
Полный скоуп и зоны правок — `.itd/SCOPE_LOCK.md`.

## Verification Standards
- Оракулы (имена — те же, что в `machine --command`):
  - `verification-profiles-oracle` = `python3 -I tests/verify_verification_profiles.py`
  - `completion-calibration-oracle` = `python3 -I tests/verify_completion_policy_calibration.py`
- `verificationCommand` пункта плана: `python3 -I tests/verify_verification_profiles.py`
- riskTier **medium** -> контуры `static + targeted`; полный `bash tests/run-all.sh`
  формально не требуется, но выполняется как часть релиза LPD-002 (exit-критерий
  сессии по `geng_session_plan.md` S01).
- RED до правки (измерено на коде до R6): операция `impact-audit` не существует
  (`operation must be select, release-evidence, diagnostics, or backlog`); поля
  `impactGraphPath` нет; карты нет. Первый прогон аудита на реальном дереве с
  generated-картой дал FAIL с двумя НАСТОЯЩИМИ дырами:
  `orphanOwned [hooks/completion-stop.sh]` (у хука не было ни одного прямого
  сьюта) и `unattachedSuites [tests/verify_review_broker_server.py]` (сьют
  достигал модуль только через `from services.review_broker import server`).
  Обе закрыты корнем, не `declared`-ребром.
- Мутации в обе стороны (все с именованной проверкой):
  1. **полнота, недоблокировка**: удалить все рёбра к сьюту -> FAIL
     `unattachedSuites == [сьют]`;
  2. **полнота**: удалить рёбра владеемого исходника -> FAIL `orphanOwned`;
  3. **пропорциональность**: объявить каждый узел смежным каждому сьюту ->
     FAIL `saturatedNodes == все узлы` при ЗЕЛЁНОЙ полноте;
  4. несуществующий узел -> FAIL `staleNodes`; несуществующая цель -> FAIL
     `staleTargets`; схема `2` -> fail-closed `DecisionError`;
  5. **мутанты движка**: снять проверку unattached / orphan / saturation ->
     соответствующая мутированная карта становится PASS (каждый гард несущий);
  6. **переблокировка**: `impactGraph` + `impactGraphPath` вместе -> отказ;
     `impactKnown:false` не читает карту и уходит в `strict.release`.
- Замер на реальном дереве: 151 сьют, 48 владеемых файлов, 341 узел,
  932 ребра, `maxClosure` 36/151 (`.itd-memory/STATE.json`) — замер на
  итоговом дереве доставки; точечная правка
  `skills/_shared/itd_verification_profiles.py` выбирает 2 сьюта из 151,
  `hooks/completion-stop.sh` — 2 (владеющий
  `verify_completion_policy_calibration.py` плюс оракул R6, который называет
  хук по пути).

## Exclusions
- Рёбра исходник -> исходник в `generated` НЕ строятся: транзитивный
  stem-матчинг насыщал 148/151 сьютов на узел (убивает пропорциональность);
  записано в BACKLOG как измеренный предел с кандидатом (точные рёбра по
  Python-импортам между исходниками).
- `run-all.sh` не переводится на карту в этом пункте: критерий требует данные
  + два оракула; потребитель карты (пропорциональный запуск сьютов) — отдельное
  решение владельца после релиза.
- Долг A5 (класс `ledger-close` и файл плана) — НЕ в этом диффе: закрывается
  отдельным коммитом/юнитом; закрытие R6 при необходимости делится, как R5.
- Скраббер, подписи, ключи, кэш ревью, новые вендоры/транспорты — `outOfScope`
  плана.

## Durable decisions (в `.itd/DECISIONS.md`)
1. **Где лежит карта.** `.itd/` (contract-данные ЭТОГО репозитория как
   ITD-проекта, рядом с `ACCEPTANCE_CONTRACT.json`), а не `skills/_shared/`
   (поехала бы в установку, где сьютов нет) и не `docs/` (это не документ).
2. **Данные + генератор, а не «ручная карта под оракулом».** Генератор даёт
   воспроизводимость, оракул `--check` делает дрейф видимым; `declared`
   оставляет человеку явный канал для ребра, которого генератор не видит.
3. **Ребро — прямой шаг.** Измерено и отвергнуто транзитивное построение.
4. **Дыры RED-прогона закрываются корнем.** `declared`-ребро к «ближайшему»
   сьюту было бы ложью о покрытии.
