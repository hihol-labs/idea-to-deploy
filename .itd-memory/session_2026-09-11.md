## Ключевые решения
- **Допуск = 60 секунд, а не 300.** Величина взята из уже действующей политики брокера:
  `github.appAuthentication.jwtClockSkewSeconds = 60` (для provenance там 300). 60 c на
  порядок больше наблюдаемого шага (-5.4 c) и впятеро меньше окна свежести.
- **Запечатанный критерий не переписывается.** Его вторая клауза допускает «объявить или
  убрать»; кандидат берёт «убрать». Сверка записана в `.itd/SCOPE_LOCK.md`.
- **Ошибочная причина в BACKLOG помечена, а не удалена**, с уроком маршрута: четыре
  конфигурации сравнивались по ОДНОМУ прогону, а одиночный прогон не отличает редкий флейк
  от детерминированной зависимости.

## Неочевидный контекст
- **Любая правка продюсера обесценивает все три efficacy-ноги** (пин — sha256 ВСЕГО файла),
  включая живой прогон на Windows. За сессию это случилось дважды.
- **Windows-нога:** `powershell.exe` НЕ в PATH из WSL, нужен полный путь
  `/mnt/c/Windows/System32/WindowsPowerShell/v1.0/powershell.exe`; скрипт `.ps1` обязан быть
  ASCII + CRLF и брать пути через `$env:APPDATA` / `$env:LOCALAPPDATA` — кириллица в имени
  пользователя ломает парсер PowerShell 5.1. Файл живёт в scratchpad, который чистится между
  сессиями: перед прогоном проверять наличие.
- **Диагностические записи архива обязаны иметь `sourceGitBlobSha1: null`.**
- **Машинная квитанция иммутабельна:** повторный прогон в тот же файл отказывает, нужна
  новая попытка (`machine-aN.json`). Идентификаторы ног обязаны совпадать с `oracleIds`
  критериев контракта, иначе матрица покрытия отвергает кандидата до вызова ревьюера.
- **Вложенная изоляция требует `--input .itd-memory/host-inputs`**: без хостового пина
  efficacy внутри кандидата краснеет, и нога зеркала падает не из-за дефекта.
- Запечатанная строка зеркала — `DONE fails: verify_reviewer_provider_freshness`: этот сьют
  красен по построению (живой пин свежести провайдера), и это единственный объявленный
  красный.
