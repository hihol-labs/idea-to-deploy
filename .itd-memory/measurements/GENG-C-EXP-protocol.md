# GENG-C-EXP — пре-регистрированный протокол (N8)

**Статус:** пре-регистрация. Записана ДО вычисления любых чисел фазы 0 и до
запуска любого живого прогона. Изменение протокола после появления чисел
допускается только новой версией с явной пометкой и причиной.

**Источник скоупа:** `.itd/DECISIONS.md` (2026-08-22, GATE G0) — «GENG-C — ОДИН
bounded-эксперимент: 12 пар, default-off, БЕЗ A и B, как обычный /task-юнит»;
`LAUNCH_PLAN.md` §«Что остаётся от GENG»; `geng_approved_roadmap.md` строка C2
(предрегистрация протокола обязательна).

## Вопрос

Находят ли **N параллельных независимых ревьюеров на ОДНОМ кандидате** то, что
сегодня приходит в **последовательных раундах 2..N**?

## Измеренное предусловие (получено до пре-регистрации, чисел не даёт)

Ни одна пара сохранившихся заходов не делит кандидата: в серии N7 (r2-r7)
дайджесты промптов попарно различны, размер растёт монотонно 527 035 -> 583 224
байт, потому что кандидат правился между заходами. Поэтому ретроспективно
«в лоб» вопрос не отвечается, и протокол делится на две фазы.

## Ключевое различение, которое и меряем

Ревьюер продюсера **без состояния**: каждый заход — свежая изолированная сессия.
Значит N последовательных заходов по **неизменному** кандидату статистически
эквивалентны N параллельным заходам, и единственная разница — латентность.
Сегодняшние раунды 2..N отличаются не параллелизмом, а тем, что **кандидат
меняется между ними**. Отсюда находки раунда k делятся на два класса:

- **PRE (пропущено раньше)** — дефект физически присутствовал в кандидате
  раунда j < k, но заход j его не назвал. Такую находку параллельный веер на
  кандидате j мог бы дать.
- **NEW (создано правкой)** — дефект появился вместе с правкой по находке
  раунда k-1; на кандидате j его не существовало. Параллельный веер дать его
  не мог **по построению**.

Доля PRE — верхняя граница пользы веера; доля NEW — нижняя граница
неустранимого хвоста (surface treadmill).

## Фаза 0 — ретроспективная декомпозиция (без затрат на модель)

Корпус: серия N7 `ORACLE-DEBT-r2..r7` (6 заходов, все BLOCKED) — единственная
сохранившаяся полная серия с промптами и отчётами.

Для каждой уникальной находки раунда k (дедуплицируется по нормализованному
тексту, как в отчётах: повторы того же дефекта из разных unit-срезов считаются
одной находкой):
1. Определить участок кода/контракта, о котором находка.
2. Проверить машинно, присутствовал ли этот участок в промпте раунда j = k-1
   (и, если да, в самом раннем сохранившемся раунде r2).
3. Классифицировать PRE / NEW / UNDECIDABLE. `UNDECIDABLE` — честный класс,
   когда участок нельзя однозначно локализовать в тексте промпта; он НЕ
   раскидывается по PRE/NEW и виден в отчёте отдельно.

**Заявлено заранее:** классификатор — не слепой (эту серию вёл я как maker).
Смягчение: класс присваивается механической проверкой присутствия участка в
байтах промпта предыдущего раунда, а не суждением; проверка оформляется
скриптом с fail-closed чекером, чтобы её мог перепроверить независимый ревьюер.

**Что фаза 0 НЕ доказывает:** она не измеряет, найдёт ли реальный параллельный
веер эти PRE-находки — только то, что у него была физическая возможность.

## Фаза 1 — живой эксперимент, 12 пар

Открывается **только по решению владельца** (стоимость ниже). Единица
наблюдения — «пара» на ОДНОМ замороженном кандидате:

- **контроль:** один заход ревьюера (как сегодня);
- **воздействие:** N = 3 независимых захода на том же кандидате, параллельно;
  вердикт кворума = BLOCKED, если BLOCKED дали >= 2 из 3.

12 пар = 12 кандидатов, по >= 4 в каждом из 3 классов:
(1) кандидат без известных дефектов (зелёный по всем оракулам);
(2) кандидат с ОДНИМ подсаженным дефектом известного класса (мутация в стиле
    существующих гардов — fail-open, ложное утверждение в контракте приёмки,
    ослабленная проверка);
(3) исторический кандидат из сохранённой серии (промпт байт-в-байт).

Заранее объявленные метрики:
- **falsePassRate(1)** — доля одиночных заходов, вернувших PASSED на кандидате
  класса (2), где дефект подсажен; **falsePassRate(quorum)** — то же для
  кворума 2-из-3. Заявленный эффект: кворум снимает >= 50% ложных PASSED.
- **latency** — wall-clock: max(N параллельных) против sum(N последовательных),
  cold и warm раздельно, обрывы транспорта остаются в выборке как UNVERIFIED
  и не выбрасываются.
- **overlap** — доля находок, названных >= 2 ревьюерами из 3 на одном
  кандидате (низкий overlap = высокая дисперсия одиночного ревьюера).

Порог решения (opt-in / stop) объявляется ДО данных: веер признаётся полезным,
если falsePassRate(quorum) <= 0.5 * falsePassRate(1) И latency(параллель) не
хуже sum(последовательных); иначе — stop, и запись в DECISIONS о том, что
измеренная польза не покрывает стоимость.

**Правило остановки:** две итерации без выхода на порог — стоп и решение
владельца, третья не запускается.

## Стоимость (замер по N7, называется до старта фазы 1)

Один заход обязательного cross-vendor продюсера на кандидате размера N7 —
порядка 10-15 минут wall-clock, платных вызовов 0 (подписка). Фаза 1 в полном
объёме = 12 x (1 + 3) = 48 заходов, то есть ~8-12 часов wall-clock, если гнать
последовательно. Дешёвая замена — субагент-чекер вместо продюсера (~1-2 минуты
на заход), но тогда измеряется нога чекера, а не обязательного ревьюера; это
разные популяции, и подмена должна быть объявлена в вердикте, а не замолчана.

## Что НЕ входит в юнит

Ни GraphSpec/NodeContract (GENG-A), ни dual-digest кэш (GENG-B) — оба закрыты
решением владельца 2026-08-22 и не воскрешаются этим экспериментом. Никакого
default-on поведения: любой результат — opt-in flag, по умолчанию выключенный.

# Поправка v2 (2026-08-28, ДО сбора данных фазы 1)

Решение владельца по фазе 1: **вариант B — удешевлённая популяция**. Записано до
получения любых чисел фазы 1.

## Что меняется

1. **Популяция ревьюера.** Вместо обязательного cross-vendor продюсера
   (~10-15 мин/заход) наблюдения снимаются субагентами-чекерами (~1-2 мин/заход,
   другая модель, свежий изолированный контекст, инструменты read-only).
   **Это другая популяция**, и вердикт юнита обязан называть подмену явно:
   результат переносится на обязательного ревьюера только как гипотеза, не как
   измеренный факт.

2. **Класс (3) «исторический кандидат».** Пре-регистрация требовала промпт
   байт-в-байт из сохранённой серии. Это неисполнимо по двум измеренным
   причинам: промежуточные деревья раундов никогда не коммитились (кандидат
   жил в индексе), а сохранившиеся промпты весят 527-583 КБ — вне практического
   бюджета субагента. Замена: исторический дефект **реконструируется снятием
   его фикса** с текущего кода; ground truth — реальная историческая находка.
   Класс называется реконструкцией, а не историей.

## Неизменное

Вопрос, единица наблюдения (пара на ОДНОМ кандидате), N = 3, кворум 2-из-3,
метрики (falsePassRate одиночный против кворума, latency, overlap), пороги
решения и правило остановки — без изменений.

## Ground truth и слепота

Каждый кандидат несёт машиночитаемый ground truth (`defectPresent: true|false`
+ описание) в манифесте, который чекерам НЕ показывается: чекер видит только
фрагмент кода и вопрос. Манифест пишется до запуска чекеров.

`defectPresent: false` для «чистых» кандидатов означает строго «известных
дефектов нет» (код прошёл маршрут и смержен), а не «дефектов нет вообще»;
находка на чистом кандидате классифицируется как noise ТОЛЬКО после разбора
по существу, а не автоматически.
