# Review broker deployment

The production boundary is an always-on HTTPS service controlled by the
dedicated GitHub App. Candidate code is never checked out or executed here.

## Secret boundary

Use four distinct credential files:

- GitHub App private key generated by the App registration;
- GitHub webhook secret generated by the App registration;
- public maker-provenance keyring;
- a rotated OpenAI Project service-account key created only for the broker.

The OpenAI key previously disclosed in chat is ineligible. Do not copy it into
`runtime/secrets`, an environment variable, an image layer, GitHub Actions, or
the repository.

For a production Linux host, prefer the systemd unit and
`systemd-creds encrypt` so secret material is exposed only through
`$CREDENTIALS_DIRECTORY` to the unprivileged `itd-review` process. The Compose
file is a local/staging parity path; it mounts secrets as read-only files,
binds HTTP only to loopback, and expects Caddy or another TLS proxy in front.

## Build and staging probe

From the repository root:

```text
docker build -f services/review_broker/Dockerfile \
  -t itd-review-broker:local .
docker compose \
  -f services/review_broker/deploy/compose.yaml \
  --env-file services/review_broker/deploy/review-broker.env \
  config
```

Create `services/review_broker/deploy/runtime/` outside Git tracking with
directories owned by UID/GID `65532`; never reuse a developer API credential.
The process intentionally refuses `OPENAI_API_KEY` in its environment.

## Dedicated GitHub App bootstrap

Create the private App only after the broker has a stable public HTTPS origin.
Preview the exact official GitHub manifest first:

```text
python scripts/itd_github_app_manifest.py \
  --organization hihol-labs \
  --broker-url https://review.example.org \
  --output-dir /secure/itd-review-app \
  --plan
```

Then start the loopback callback and open the printed local URL in the browser:

```text
python scripts/itd_github_app_manifest.py \
  --organization hihol-labs \
  --broker-url https://review.example.org \
  --output-dir /secure/itd-review-app \
  --serve --apply
```

The manifest requests only `checks:write`, `contents:read`,
`pull_requests:read`, and metadata access, and subscribes only to
`pull_request` and `merge_group`. It writes the RSA private key, webhook
secret, and non-secret registration record outside the repository with mode
`0600`; the generated OAuth client secret is deliberately discarded. Install
the App only on controlled repositories.

After the App has emitted its first Check Run, apply the App-bound ruleset and
observe the exact live enrollment:

```text
itd gate enrollment \
  --repository hihol-labs/example \
  --scope organization \
  --ruleset-id <active-ruleset-id> \
  --app-id <dedicated-app-id> \
  --app-slug <dedicated-app-slug> \
  --workflow-repository-id <itd-release-repository-id> \
  --workflow-sha <pinned-itd-release-sha> \
  --output /secure/example-enrollment.json

itd gate enrollment \
  --repository hihol-labs/example \
  --scope organization \
  --ruleset-id <active-ruleset-id> \
  --app-id <dedicated-app-id> \
  --app-slug <dedicated-app-slug> \
  --workflow-repository-id <itd-release-repository-id> \
  --workflow-sha <pinned-itd-release-sha> \
  --output /secure/example-enrollment.json \
  --apply
```

The second command persists only metadata observed from GitHub. Feed that
receipt to the broker operator; do not hand-author or edit it.

## Enrollment operator

Preview and apply a public provenance record:

```text
python -m services.review_broker.operator keyring-add \
  --keyring /secure/provenance-keyring.json \
  --record /secure/repository-public-key.json

python -m services.review_broker.operator keyring-add \
  --keyring /secure/provenance-keyring.json \
  --record /secure/repository-public-key.json \
  --apply
```

Restart the broker after a new keyring entry. Then preview/apply the
schema-validated live enrollment receipt:

```text
python -m services.review_broker.operator enroll \
  --database /var/lib/itd-review-broker/review-broker.sqlite3 \
  --keyring /secure/provenance-keyring.json \
  --receipt /secure/enrollment-receipt.json

python -m services.review_broker.operator enroll \
  --database /var/lib/itd-review-broker/review-broker.sqlite3 \
  --keyring /secure/provenance-keyring.json \
  --receipt /secure/enrollment-receipt.json \
  --apply
```

An active enrollment is immutable. App or ruleset rotation requires an
explicit disable/rotation procedure and a freshly observed receipt; editing
the database is never supported.

## Readiness and exposure

Expose only the TLS proxy. `/healthz` proves the process is alive. A repository
is gate-ready only when:

```text
GET /readyz?repository=<owner/repo>&appId=<dedicated-app-id>
```

returns HTTP 200 with the exact policy SHA, reviewer routes, positive budget
admission, active enrollment receipt, and matching public provenance key.
Reverse-proxy access logs must not include request bodies or authorization
headers. Back up the SQLite database atomically (SQLite backup API or a stopped
service copy), test restoration, and retain the encrypted credentials
separately.
