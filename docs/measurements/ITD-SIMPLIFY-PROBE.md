# ITD-SIMPLIFY-PROBE - проба «до/после» программы ADR-016 (сессия 13)

Проба - дешевая ступень перед A/B: те же зафиксированные задачи на эталоне и на текущей установке, сравнение трасс
(процессы хуков, время, решения гейтов, результат). Корректность методологии проба не доказывает и A/B не заменяет
(поправка плана 2026-10-30). Протокол ниже остается для будущих изменений ITD: изменение, которое не проходит пробу,
до A/B не доходит.

Эталон - замер сессии 2 (`docs/measurements/ITD-SIMPLIFY-BASELINE.md`, установка 1.109.2, main `162c9d3`) и его
сырые раунды `bench-before-*`. Текущая установка - runtime `1.110.5-23a8eadd4ffd5675` на WSL и Windows, main
`10f970c`; дайджест дерева runtime (`runtime_digest.py`, 51 файл) на обоих хостах
`ba6487a3338b8f04d9a7f63bb3b6ba6d8b89dbdd1c5de008c0a963b49f571eca`. Замер 2026-11-06 07:52-07:57Z.

## 1. Протокол пробы

### 1.1. Зафиксированные задачи

| Задача | Что подается | Чем меряется |
|---|---|---|
| T1 | вызов Bash `git status --short` | `hook_bench.py`: процессы, Pre, Post, цепочка |
| T2 | вызов Edit файла `README.md` | то же |
| T3 | вызов Read файла `README.md` | то же |
| T4 | восемь решений гейта PreToolUse (таблица раздела 2.3) | решение диспетчера на каждый вход |
| T5 | учетное закрытие релиза по конвенции ADR-016 | время и число модельных раундов по записям леджера |

T1-T3 - инертные нагрузки `hook_bench.py` (инструмент не исполняется), четыре сочетания «хост x проект» (WSL x ITD,
WSL x buying, Windows x buying, Windows x ITD), три раунда по 10 вызовов после одного прогрева. T4 подает вход
PreToolUse на stdin зарегистрированной команде диспетчера; хуки только выносят решение, ничего не исполняется и не
отправляется.

### 1.2. Одинаковые условия

- Тот же скрипт (`hook_bench.py` не менялся после `c94c50a`), те же нагрузки, те же четыре сочетания, тот же
  порядок раундов и то же правило нагрузки: раунд стартует при 1-минутной нагрузке WSL ниже 1.5 (`run_rounds.sh`).
- Сводка - `summarize_rounds.py`: медиана трех медиан цепочки; фаза с ненулевым выходом хука или пропуском раунда
  сводкой отвергается.
- Время берется по меткам стенда и по записям транскриптов (`transcript_stats.py`), а не по самооценке агента.

### 1.3. Как повторить

```bash
RAW=.itd-memory/host-inputs/<юнит> SINCE=<дата раскатки> bash docs/measurements/itd-simplify/run_rounds.sh <фаза> 3
python3 docs/measurements/itd-simplify/summarize_rounds.py .itd-memory/host-inputs/<юнит> before <фаза>
python3 docs/measurements/itd-simplify/runtime_digest.py <runtime WSL> <runtime Windows>
```

Решения гейта (T4) повторяются по приложению A: там точные входы и порядок вызова.

Раунды эталона `bench-before-*` и `meta-before.txt` копируются в каталог фазы из
`.itd-memory/host-inputs/ITD-PLAN-S3/`. Во время раундов на машине не должно идти другой тяжелой работы: первый
запуск этой пробы (07:44Z) шел одновременно с разбором транскриптов и отброшен целиком
(`.itd-memory/host-inputs/ITD-PLAN-S13/discarded-run1/`), в таблицы вошел только повтор.

### 1.4. Чего проба не делает

- Живые задачи агента на двух установках не запускались. Причины: эталонной установке нужен свой домашний каталог со
  вторым входом в учетную запись (копия файла учетных данных рискует входом владельца), а один прогон модели на
  задачу не отличим от выброса. Поэтому число вызовов инструментов агентом и его ошибки проба не сравнивает; для
  поведения модели предназначен пилот по `ITD-PILOT-TESTGAP-PROTOCOL.md` с N прогонов на вариант.
- Эталон и текущая установка измерены в разные дни (2026-10-22 и 2026-11-06) и не чередовались; харнесс Claude Code
  за это время обновился (2.1.304 -> 2.1.317 в транскриптах).
- `egress_acceptance_probe.py` на текущей раскладке не работает: он ищет в `settings.json` прямую регистрацию
  `pii-egress-guard`, а с сессии 6 там один диспетчер на событие. Те же три случая поданы диспетчеру напрямую
  (раздел 2.3); правка скрипта - в BACKLOG.

## Приложение A. Входы T4 и порядок вызова

Команда - первая команда раздела `hooks.PreToolUse` в `settings.json` хоста, в которой есть `claude-dispatch`
(`~/.claude/settings.json` на WSL, `/mnt/c/Users/<пользователь>/.claude/settings.json` для Windows; при запуске
Windows-команды из WSL начало `"C:/` заменяется на `"/mnt/c/`, аргументы остаются Windows-путями). Команда
запускается через оболочку с рабочим каталогом `/tmp` (WSL) или `/mnt/c/Users/<пользователь>` (Windows), на stdin -
один JSON:

```json
{"session_id": "itd-s13-probe", "transcript_path": "", "cwd": "<рабочий каталог>", "hook_event_name": "PreToolUse", "tool_name": "<tool_name случая>", "tool_input": <tool_input случая>}
```

Решение - поле `hookSpecificOutput.permissionDecision` последней строки stdout. «Без решения» (`none`) - код выхода
0 и поля нет; для случаев с ожиданием `ask` или `deny` годится любое из двух. Случаи в порядке таблицы раздела 2.3,
по одному в строке:

```json
{"case": "host-ui-tool", "tool_name": "mcp__ccd_turn__update_plan", "tool_input": {"items": [{"content": "probe", "status": "pending"}]}, "expected": ["none"]}
{"case": "ssh-path-scan", "tool_name": "Bash", "tool_input": {"command": "ls -la /tmp/ssh-d2719c3f/agent.1", "description": "probe"}, "expected": ["none"]}
{"case": "http-post-external", "tool_name": "Bash", "tool_input": {"command": "curl -d 'a=1' https://example.com/api", "description": "probe"}, "expected": ["ask", "deny"]}
{"case": "subst-next-to-cd", "tool_name": "Bash", "tool_input": {"command": "cd ~/projects/idea-to-deploy && echo \"$(git rev-parse --short HEAD)\"", "description": "probe"}, "expected": ["none"]}
{"case": "dash-d-local", "tool_name": "Bash", "tool_input": {"command": "ls -d /tmp/*/ | head -3", "description": "probe"}, "expected": ["none"]}
{"case": "sandbox-regex-words", "tool_name": "mcp__plugin_context-mode_context-mode__ctx_execute", "tool_input": {"language": "python", "code": "import re\nrx = re.compile(r'Windows|PowerShell|pwsh|cmd\\.exe|CRLF|\\$null|py -3')\nprint(bool(rx.search('plain text')))\n"}, "expected": ["none"]}
{"case": "sandbox-plain", "tool_name": "mcp__plugin_context-mode_context-mode__ctx_execute", "tool_input": {"language": "python", "code": "print(sum(range(10)))\n"}, "expected": ["none"]}
{"case": "git-push", "tool_name": "Bash", "tool_input": {"command": "git push origin HEAD", "description": "probe"}, "expected": ["ask", "deny"]}
```

Хуки только выносят решение: ни одна команда из `tool_input` не исполняется, наружу ничего не уходит. Результат
2026-11-06 на обоих хостах: `none`, `none`, `ask`, `none`, `none`, `none`, `none`, `ask`.
